# 바람 배달부 — 비행·코어 루프

> 정리일: 2026-09-18 · 상태: 설계 초안
> 조작·기류·고도·연료의 규칙과 수치 가설을 관리한다. 모든 수치는 실측 전이며, 서로 다른 후보를 함께 채택한 것이 아니다.

## 1. 루프 계층

이 게임에는 네 개의 중첩된 루프가 있다. 아래로 갈수록 길고, 위로 갈수록 손에 가깝다.

| 계층 | 주기 | 플레이어가 하는 일 | 결정의 성격 |
|---|---|---|---|
| 마이크로 루프 | 실측 후 결정 (초기 가설 140초) | 고도 확보(엔진 또는 기류) → 활공 | 반사와 관찰 |
| 코어 루프 | 실측 후 결정 | 마을 한 곳에 배달 | 경로 판단 |
| 데일리 루프 | 실측 후 결정 | 하루치 노선 완주 → 귀환 → 정산 | 위험 관리 |
| 메타 루프 | 수 시간 | 수입·정비·기체 꾸미기·서랍 편지 → 막 전환 | 목표 설정 |

첫 검증은 마이크로 루프에 집중하고 저공 투하 후 비행 재개까지 확인한다. 하루 전체 흐름은 후속 단계다. 범위는 [프로토타입 검증](P.프로토타입검증.md)에서 관리한다.

## 2. 마이크로 루프 — 게임의 심장

### 2.1 사이클 구조

```
  [기류 탐색]  →  [선회 상승]  →  [이탈·활공]  →  [고도 소진]
      20초           30초            90초          → 반복
      관찰           노동             보상
```

**2026-09-24 사용자 결정: 기류는 필수가 아니라 선택이다.** 실측에서 위 사이클은 일어나지 않았다. 2026-09-21~23 완주한 하루 27회의 기류 방문 70회 중 선회(270도 이상)는 1회뿐이고, 나머지는 10초 남짓 곧게 통과했다. 기류 상승 시간과 하루 끝 연료 사이에도 관계가 없었다. `hold A or D to circle in it` 안내를 넣은 뒤에도 선회는 0회였고, 사용자는 "문구는 봤는데 돌 필요를 못 느꼈어"라고 답했다. 원인은 조작이 아니라 구조다 — 연료가 넉넉해(가까운 배달 끝 약 66%, 장거리 약 40%) 공짜 고도가 필요 없다. 이를 기류를 강제하는 새 규칙으로 뒤집지 않는다(쉬운 쪽·규칙 추가 금지 원칙). 따라서 실제 마이크로 루프는 **고도 확보(엔진 출력 보조, 또는 원하면 기류) → 활공**이며, 효율을 가르는 것은 활공 비율이다(장거리 7회에서 활공 79% → 2.09 %/km, 47% → 5.14 %/km). 기류는 연료 없이 고도를 주는 선택지로 남기고, 아래 사이클 표와 140초는 폐기된 초기 가설로 기록만 남긴다([측정 기록](P.프로토타입_측정기록.md)).

2026-09-18 사용자 결정(D10): 첫 테스트의 마이크로 루프 1회는 **탐색 20초 + 상승 30초 + 활공 90초 = 140초(2분 20초)**를 기준으로 통일한다. 각 구간 시간은 실측으로 조정할 초기 가설이며, 고정 타이머나 모든 기체에 강제하는 주기가 아니다. 탐색·상승·활공 시간을 각각 기록해 체감과 함께 판단한다.

### 선회 상승 보조

2026-09-18 사용자 결정: 상승기류를 찾고 진입하는 것은 플레이어가 담당하고, 진입 후에는 선회를 약하게 보조해 상승을 유지하기 쉽게 한다. 이 방식을 첫 프로토타입에 포함한다.

- 플레이어가 방향을 조작하면 즉시 보조에서 벗어나 직접 조종한다.
- 기류를 자동으로 찾아가거나, 목표 고도까지 자동으로 상승시키지 않는다.
- 보조는 기류 안에서만 작동하고 이탈하거나 기류가 소멸하면 해제한다.
- 첫 테스트에서는 기류 중심을 향한 선회 보정 중 최대 20%만 적용한다. 기류 안에 0.5초 이상 머물고 방향 입력이 없을 때 발동하며, 방향 입력이 15% 이상 들어오면 즉시 해제한다. 기류를 벗어나면 해제하고, 다시 진입한 뒤 0.5초 동안 입력이 없으면 재발동한다. 수치는 조작감 실측 후 조정한다.

### 2.2 설계 규칙 — 상승 1 : 활공 3

**오르는 것은 노동이고, 활공은 보상이다.** 이 비율이 뒤집히면 게임은 노동이 된다.

이 비율에서 나머지 수치가 자동으로 도출된다.

- 활공 90초 동안 잃는 고도 = 상승 30초 동안 버는 고도
- 따라서 **순상승률 = 침하율 × 3**
- 순상승률 = 기류 상승률 − 침하율 이므로, **기류 상승률 = 침하율 × 4**

> 이 계산은 상승·활공 비율을 시험하기 위한 가설이다. 기체마다 동일한 비율을 강제하지 않는다. 2026-09-18 사용자 결정(D10): 같은 장소·환경 조건의 바람과 상승기류는 기체와 무관하게 유지하며, 기체 교체에 맞춰 기류를 자동 조정하지 않는다. 날씨와 기류 생명 주기에 따른 변화는 유지한다.

같은 노선에서 기체별 차이를 느끼도록 침하율·활공 성능·조종 반응으로 차이를 낸다. Jenny는 기류 진입과 선회가 쉽고, DH-4는 적재·장거리에 유리하되 상승과 선회가 둔하며, Mailwing은 약한 기류를 활용하고 얻은 고도로 오래 활공하는 방향이다. 구체적인 수치는 후속 비행 실측으로 정한다(D05·D10).

### 2.3 기체별 초기 수치

**기체 역할·해금은 [게임플레이](04.게임플레이.md)의 D05 확정안을 따른다.** 아래 표는 2026-09-18 사용자 결정에 따라 첫 테스트 기준으로 사용한다. 최종 성능 비교표가 아니며, 테스트 전에 기체 간 차이를 추가로 벌리지 않는다. 첫 검증은 Jenny로 시작하고, 후속 비교는 같은 기류 조건에서 진행한다.

2026-09-18 사용자 결정: 첫 완성판의 기체 개조는 도장·외형 꾸미기로 한정한다. 꾸미기에 따른 비행 성능 변화는 없으며, 기체별 수치는 성능 개조 조합 없이 검증한다.

**읽는 법**

- ‘필요 기류’는 이전 1:3 비율 가설에서 역산한 값이며, 기체별 월드 기류 설정이나 상승 가능한 최소 기류를 뜻하지 않는다. 각 행의 순상승률·사이클 고도는 서로 다른 기류를 가정했으므로 동일 환경의 기체 성능 비교에 사용하지 않는다. 후속 비교에서는 같은 기류 조건으로 다시 측정한다.
- 이 표의 동일한 사이클 수평거리는 고정 속도·활공 시간에서 나온 계산값이다. DH-4의 장거리 역할이나 실제 항속 거리를 제한하는 기준으로 사용하지 않는다. 적재량·연료 용량·소비율은 별도로 검증한다.
- Mailwing은 바람 활용과 활공의 이점이 느껴져야 한다. 위 고도 계산만으로 섬세한 조종감이 검증된 것은 아니다.
- 활공비는 실기 성능이 아니라 게임 리듬에서 역산한 값이다. 고증보다 리듬을 우선한다.

### 2.4 기류 탐색 — 플레이어가 무엇을 보고 찾는가

기류가 눈에 보이면 게임이 아니라 심부름이 된다. 반대로 완전히 안 보이면 운이 된다. **단서는 존재하되 해석이 필요해야 한다.**

| 단서 | 감지 거리 | 신뢰도 | 비고 |
|---|---|---|---|
| 스카프 흔들림·기체 기울기 | 0 m (진입 직후) | 확실 | 1차 지표. 한쪽 날개만 들리면 그쪽에 기류 |
| 새떼의 선회 | 800 m | 높음 | 가장 알아보기 쉬운 원거리 단서 |
| 적운 밑면 | 2000 m | 중간 | 이미 소멸 중일 수 있음 |
| 굴뚝 연기·마을 화덕 | 600 m | 높음 | 마을 근처에 기류가 몰리는 이유 |

### 3.1 배달·하루 시간 산정

**2026-09-18 사용자 결정(D10): 준비·귀환·정산은 하루에 한 번 계산하고, 이동·접근·투하·고도 회복은 배달마다 계산한다.** 서사 배달에는 착륙·대화·재이륙 시간을 별도로 반영한다. 배달 횟수와 하루 길이는 실측 후 정한다.

| 구분 | 계산 범위 | 측정 방식 |
|---|---|---|
| 하루 공통 | 출발 준비·최초 이륙, 마지막 배달 이후 귀환·정산 | 하루에 한 번 합산 |
| 일반 배달 | 직전 지점에서 목적지까지 이동·접근·투하·고도 회복 | 배달마다 측정. 놓친 경우 재접근 시간 포함 |
| 서사 배달 | 목적지까지 이동·접근, 착륙·전달·대화·재이륙·고도 회복 | 해당 배달마다 측정. 저공 투하 대신 착륙 전달 구간 적용 |
| 그 밖의 활동 | 선택적 탐색·정비·편지 읽기·생활 대화·서사 장면 | 실제 수행 시간을 별도로 합산 |

하루 총 시간 = 하루 공통 시간 + 각 배달 시간의 합 + 그 밖의 활동 시간.

고도 회복과 다음 목적지로의 이동이 겹치면 경과 시간은 한 번만 합산한다. 마지막 배달 뒤 귀환과 고도 회복이 겹치는 경우도 같다. 각 활동의 세부 로그는 남기되 하루 총 시간에는 중복으로 더하지 않는다. 서사 배달에서 이미 측정한 대화·장면도 별도 활동에 다시 더하지 않는다.

140초는 마이크로 루프 1회의 초기 테스트 기준이며, 배달마다 2사이클을 강제하지 않는다. 이전의 순항 250초·배달 6분 40초, 2사이클로 환산한 7분 10초, 하루 15~20분은 현행 시간 목표로 사용하지 않는다. 실제 노선과 배달 방식별 측정 결과로 배달 횟수·하루 길이를 산정한다.

### 3.2 핵심 설계 — 배달은 고도를 지불한다

**투하 판정 확정(2026-09-18 사용자 결정, D02): 넓은 배달 구역 안에서 적정 고도를 만족하면 투하 가능 표시를 제공하고, 버튼 하나로 배달을 성공시킨다.** 정밀 조준·타이밍 점수는 사용하지 않는다. 투하하지 않고 지나치면 우편을 유지한 채 재접근하며, 조건 밖의 입력으로 우편을 소모하지 않는다.

첫 테스트의 투하 판정은 배달 중심점 반경 80 m 이내, 고도 120 m 이하, 상승 중이 아닌 상태(수평 비행 포함, 수직 속도 +0.5 m/s 미만)로 둔다(2026-09-19 변경). 속도와 방향에는 별도 정밀 점수나 각도 판정을 두지 않는다. 조건을 만족하면 E 입력으로 투하하고, 조건 밖에서 E를 눌러도 우편을 소모하지 않는다. 반경·허용 고도·상태 표시와 버튼은 실측 후 조정한다.

**투하 접근 안내 갱신 확정(2026-09-19 사용자 결정): 노란색 접근 예고 중 조건을 벗어나면 현재 필요한 조작 안내로 즉시 갱신한다.** 고도가 높으면 “고도를 낮추세요”, 상승 중이면 “상승을 멈추세요”를 표시하고, 두 조건이 함께 부족하면 고도 안내를 우선한다. 조건을 충족하면 초록색 투하 안내와 E 입력을 표시한다. 접근 거리 300 m 안의 노란색 안내 자체는 유지하되, 고도·수직 속도 상태에 따라 문구를 바꾼다. 안내 문구와 표시 우선순위는 후속 UI 검증에서 조정한다.

**투하 접근 안내 범위 확정(2026-09-19 사용자 결정): 수평 거리 300 m 밖으로 벗어나면 접근 안내를 즉시 숨긴다.** 다시 300 m 안으로 접근하면 현재 조건에 맞는 노란색 접근 안내를 새로 표시하고, 조건 충족 시 초록색 투하 안내로 전환한다. 안내를 오래 남겨 목적지 방향과 혼동시키지 않도록 하며, 거리 경계에서의 깜박임과 표시 전환은 후속 UI 검증에서 조정한다.

**투하 안내 우선 표시 확정(2026-09-19 사용자 결정, D07): 노란색 접근 안내나 초록색 투하 가능 안내가 표시되는 동안 목적지 표식을 잠시 숨긴다.** 투하 상태와 필요한 조작을 먼저 읽게 하며, 안내가 사라지거나 배달이 완료되면 목적지 표식을 다시 표시한다. 목적지 방향·거리 정보는 유지하고, 월드의 목적지 표식만 겹치지 않게 감춘다. 전환 시점과 안내 가독성은 후속 UI 검증에서 조정한다.

투하를 위해 고도를 낮추면 현재 가설의 기류 유효 고도대(200 m) 아래로 내려간다. **2026-09-18 사용자 결정(D10): 투하 후에는 엔진 출력 보조만으로 기류에 다시 진입할 고도까지 회복할 수 있게 한다.** 플레이어가 자세와 경로를 조종하며, 상승기류에 진입하면 더 수월하게 고도를 확보할 수 있다. 투하 고도·기류 유효 고도·회복 시간·상승력은 실측 후 조정한다.

능선 바람(사면 상승)의 구현 여부는 첫 검증 결과를 보고 결정한다. 첫 검증에서는 능선 바람 없이도 투하 후 고도를 회복하고 비행을 이어갈 수 있어야 한다.

그래서 서사(편지를 전한다)와 메커닉(고도를 관리한다)이 **같은 자원을 쓴다.** 가까운 노선에서는 고도 복구에 필요한 연료를 넉넉히 제공하고, 장거리에서만 배달 순서와 고도 복구 비용이 연료 판단으로 이어지게 한다.

착륙 배달은 서사가 있는 마을과 서랍 편지의 수취인 등 중요한 서사 전달에 사용한다. **2026-09-18 사용자 결정(D10): 전달·대화를 마치면 준비된 이륙 위치에서 출발하고, 지상 활주 조작을 간소화해 출력 보조로 재이륙한다.** 가까운 배달은 재이륙과 고도 회복에도 연료 여유를 제공한다. 구체적인 활주 보조 범위·배치 전환 연출은 후속 검증에서 정한다.

재이륙·고도 회복의 소요 시간과 연료량은 후속 착륙 전달 테스트에서 측정한다. 이 시간을 서사 배달 구간에 포함하며, 기존의 “고도 복구는 필요 없다”는 표현은 현행 규칙으로 사용하지 않는다.

재이륙 초기 구현은 지정된 활주 지점으로 **1.5초 동안 카메라를 전환하는 동안 다음 목적지 방향으로 기체를 부드럽게 자동 정렬하고, 약 2초의 짧은 활주 뒤 자동 이륙**을 진행한다(2026-09-19 사용자 결정). 플레이어가 지상에서 방향을 맞추거나 출력 보조를 누를 필요는 없다. 지상 이동은 짧게 보조하며, 직접 활주를 길게 요구하지 않는다. **착륙 전달의 지정 이륙 지점은 수취인 장소에서 가깝고 안전한 평지에 배치한다(2026-09-19 사용자 결정).** 전달 장소의 여운을 유지하되 주변 장애물·경사·충돌 위험을 피할 수 있는 위치를 우선한다. 보급 지점의 이륙 위치도 같은 기준을 따르며, 이륙 후에는 일반 비행 조작으로 돌아간다.

자동 활주 중 장애물이나 위험 지형이 감지되면 활주를 중단하고 안전 지점에 정지한다(2026-09-19 사용자 결정). **같은 이륙 지점에서 위험이 사라질 때까지 시간 제한 없이 대기**하며, 대기 중에는 플레이어 입력을 무시하고 안전 상태를 유지한다(2026-09-19 사용자 결정). 중단 안내는 3초 동안 표시한 뒤 숨기고, 위험이 해소되면 같은 절차로 자동 활주·이륙을 다시 시작한다(2026-09-19 사용자 결정). 자동 이륙을 강행해 충돌시키지 않으며, 플레이어가 다른 지점을 고르는 분기를 기본으로 만들지 않는다. 감지 거리·재시작 절차는 후속 재이륙 테스트에서 조정한다.

### 착륙 접근과 접지 보조

**착륙 보조 중 카메라 확정(2026-09-19 사용자 결정, D04): 기존 비행 카메라를 유지한다.** 직접 접근부터 보조 시작·접지·정지까지 같은 비행 시점을 이어간다. 착륙 완료 후 전달 장면과 재이륙의 카메라는 각 장면의 별도 규칙을 따른다.

2026-09-18 사용자 결정(D04), 2026-09-19 보조 범위·시작 방식 결정: 착륙 지점까지의 접근은 플레이어가 조종한다. 속도·고도·방향의 **넓은 허용 범위**에 들어온 상태에서 **E 버튼을 누르면 착륙 보조를 시작한다.** 조건 충족만으로 자동 시작하지 않으며, 보조가 시작되면 약간의 접근 오차를 흡수해 마지막 접지와 정지를 돕는다. 조건 밖에서 E를 누르면 보조를 시작하지 않고 재접근할 수 있게 한다. 2026-09-19 사용자 결정: 보조 시작 후에는 중간 취소 없이 접지·정지까지 진행한다. E를 다시 눌러도 취소하지 않으며, 기체가 정지하면 착륙 보조를 종료한다. 허용 범위·보조 강도는 후속 착륙 테스트에서 조정한다. 조건 미충족 자체로 실패 처리하지 않으며 실제 충돌 시에는 [게임플레이](04.게임플레이.md)의 복귀 원칙을 따른다. 아래 이전 참고안의 “활주로 근처에 가면 자동 접지” 대신 이 조건부 보조 원칙을 적용한다.

**착륙 조건 미충족 안내 확정(2026-09-19 사용자 결정, D04·D07): 착륙 접근 중 조건이 부족하면 필요한 조작을 짧은 문구로 표시한다.** 현재 충족하지 못한 속도·고도·방향 조건에 맞춰 안내한다. 문구 예시는 과속 시 “속도를 줄이세요”, 고도가 높을 때 “고도를 낮추세요”, 방향이 맞지 않을 때 “착륙 방향을 맞추세요”다. 조건을 충족하면 E 버튼으로 착륙 보조를 시작할 수 있음을 표시한다. 최종 문안·표시 시점·여러 조건이 부족할 때의 표시 우선순위는 후속 착륙·UI 검증에서 조정한다.

### 3.3 엔진 조작 — 간단한 입력

**결정 방향(2026-09-18): 엔진 출력 조작은 간단하고 쉽게 한다.** 성능이 낮은 기체의 느낌은 복잡한 조작 대신 완만한 가속과 제한된 상승력으로 표현한다. 저공 배달 뒤 다시 오르는 과정이 지루할 정도로 느려져서는 안 된다.

2026-09-18 사용자 결정(D03): 다음 게임패드 입력을 첫 테스트의 기준으로 채택한다. 사용성은 실측 후 조정한다.

| 입력 | 동작 |
|---|---|
| 기본 상태 | 자동 순항. 자세와 경로는 플레이어가 조종한다 |
| 오른쪽 트리거(RT)를 누르는 동안 | 출력 보조. 놓으면 자동 순항으로 복귀 |
| 왼쪽 트리거(LT)를 한 번 누름 | 순항과 활공을 전환. 활공은 엔진을 끈 상태이며 버튼을 놓아도 유지 |
| 활공 중 RT를 누름 | 활공 해제 후 출력 보조. RT를 놓으면 활공이 아닌 순항으로 복귀 |

동시 입력의 초기 처리 규칙은 RT 우선으로 둔다. RT를 누르는 동안 LT 입력은 무시하며, RT를 놓은 뒤 새로 LT를 눌러야 활공을 시작한다. LT는 누른 순간 한 번만 전환하고 길게 누르고 있어도 반복 전환하지 않는다. 이 우선순위는 첫 테스트에서 혼동 여부를 확인한다.

키보드의 첫 테스트 배치는 다음과 같다. WASD는 방향 조종, Left Shift를 누르는 동안 출력 보조, Left Ctrl을 한 번 누르면 순항·활공 전환, E는 투하·착륙·보급 상호작용이다. 게임패드와 같은 상태 전환을 사용하며, Shift가 눌린 동안 Ctrl 입력은 무시하고 Shift를 놓은 뒤 다시 Ctrl을 눌러야 전환한다. 키는 재배치할 수 있게 두고, D07의 간단한 엔진 상태 표시는 실제 상태와 일치시킨다.

정밀 스로틀 조절이나 엔진 관리 절차를 요구하지 않는다. 엔진으로 기본 비행은 가능하며, 상승기류는 더 수월한 고도 확보와 긴 활공을 제공한다.

### 3.4 연료 — 장거리 비행의 경로 판단

**결정 방향(2026-09-18): 연료는 장거리 비행에서만 실질적인 제약으로 작용한다.** 가까운 일상 배달은 엔진 위주로 날고 재접근·고도 복구를 해도 충분한 여유가 있어야 한다. 연료 부족으로 활공을 강제하지 않는다.

장거리에서는 바람 활용, 우회 거리, 출력 보조 사용이 도달·귀환 여유에 영향을 준다. **2026-09-18 사용자 결정(D03): 출발 전에 장거리 노선 표시·예상 왕복 연료 소모량·중간 보급 가능 여부를 안내한다.** 가까운 배달의 연료 부담은 낮게 유지하며, 장거리의 구체적인 거리 기준과 소비량은 실측 후 정한다.

예상 왕복 소모량은 계획한 노선의 추정치로 제시한다.

**연료 부족 시 출발 허용 확정(2026-09-19 사용자 결정, D03): 현재 연료가 예상 소모량보다 부족해도 경고 후 출발을 허용한다.** 보급 경유가 필요하면 해당 지점을 함께 안내하고, 최종 출발 판단은 플레이어에게 맡긴다. 첫 보급 지점까지의 예상 연료가 부족한 경우에도 이를 경고하되 출발을 제한하지 않는다. 부족 판정의 여유와 경고 표현은 후속 연료·UI 검증에서 조정한다.

**예상 소모량 계산 기준 확정(2026-09-19 사용자 결정, D03): 순항을 기본으로 하고, 이륙·재이륙과 투하 후 고도 회복 등에 필요한 출력 보조의 연료 소모를 포함한다.** 기류·활공으로 절약할 연료는 예상 소모량에서 미리 차감하지 않는다.

**조건부 표시로 재개정(2026-09-21 사용자 결정, D03).** 아래 범위 표시까지 적용한 뒤에도 사용자 평가는 **"봤는데 신경은 안 썼어"**였다. 세 가지 형태(한 숫자·범위·게이지 아래 상주)를 모두 시험했으나, 탱크가 넉넉히 덮는 노선에서는 어떤 숫자도 행동을 바꾸지 않았다. 일곱 번의 장거리 비행에서 실제로 판단을 만든 것은 **실시간 연료 게이지와 30%·15% 경고, 그리고 보급 지점 표식**이었다(4일차에 15%에서 "소비를 줄여서 보급까지 갔다"). 따라서 **예상치는 빠듯한 노선에서만 표시한다**: 잘 날았을 때의 예상이 탱크의 70%를 넘는 노선에서만 카드와 HUD에 띄우고, 그 아래에서는 카드에 "탱크로 왕복이 덮인다"는 한 줄만 남긴다. 기능을 삭제하지 않고 할 말이 있을 때만 말하게 하는 쪽을 택했으며, 화면 한구석을 무시하도록 학습시키는 것을 막는 것이 목적이다. 현재 10km 노선은 표시되지 않는다.

**범위 표시로 개정(2026-09-21 사용자 결정, D03).** 위 기준을 한 숫자로만 보여주면 10km 왕복에 약 128%가 나오는데 실측은 78.7%였다(5일차). 즉 5분의 1을 남기고 돌아올 수 있는 노선에 "보급 필수"라고 단정했고, 사용자는 첫 장거리에서 "카드를 봤지만 읽지 않았다"고 평가했다. **한 숫자 대신 범위를 보여준다**: 낮은 값은 잘 날았을 때 실제로 든 비용, 높은 값은 위의 기준 그대로(전 구간 순항, 활공·기류 무차감)다. 활공을 미리 차감하는 것이 아니라 양쪽 끝을 함께 말하는 것이므로 위 원칙과 충돌하지 않는다. **보급 필요 경고는 낮은 값이 탱크를 넘볼 때만** 띄워 헛경고를 없앤다. 낮은 값은 계산이 아니라 **실측값**(2026-09-21 20km에 78.7%·80.7%, km당 약 3.9%)이며, 출발 고도·D와 귀환 지점으로의 하강·노선상 기류가 주는 공짜 거리를 이론으로 재기 어렵기 때문이다. 측정이 쌓이면 [측정 기록](P.프로토타입_측정기록.md)에서 재보정한다. 같은 경로에서 기류·활공을 활용하면 실제 소모량이 줄어 연료 여유를 얻을 수 있다. 실제 소모량은 경로와 출력 보조 사용 등에 따라 달라질 수 있으므로, 구간별 소비량·출력 보조 시간·왕복 연료 여유는 후속 실측으로 정한다.

정규 우편 선택 화면에서는 목적지·거리·적재량과 장거리 표시를 함께 보여주고, 장거리인 경우 예상 왕복 연료 소모량과 보급 가능 여부를 같은 카드에 표시한다. 이 정보는 출발 전 판단을 돕는 요약이며, 실제 비행 중 연료 게이지와 대체하지 않는다.

**출발 전 연료 표시 형식 확정(2026-09-19 사용자 결정, D03): 장거리 노선 카드에 게이지와 예상 왕복 소모 비율(%)을 함께 표시하고, 중간 보급 가능 여부를 곁들인다.** 문구 예시는 “왕복 약 70% · 중간 보급 가능”이다. 70%는 표시 예시이며 확정 소비 수치가 아니다. 게이지의 세부 표현은 후속 UI 검증에서 다듬는다.

**보급 경유 필요 안내 확정(2026-09-19 사용자 결정, D03): 예상 연료 소모 기준으로 보급 경유가 필요한 노선에는 출발 전 카드에 “중간 보급 필요”와 해당 보급 지점을 함께 표시한다.** 출발 전 지도에서도 해당 지점을 확인할 수 있게 한다. 경유 필요 판정에 적용할 연료 여유와 임계값은 후속 연료 검증에서 정한다.

**중간 보급 방식 확정(2026-09-18 사용자 결정, D03): 일부 마을의 지정 착륙 지점에서 간단한 상호작용으로 보급하고, 출발 전 지도에 해당 지점을 표시한다.** **보급량·비용 확정(2026-09-19 사용자 결정): 보급 시 현재 기체의 연료를 최대 용량까지 무료로 채운다.** 보급 지점을 경유하는 경로 선택에 집중하도록 한다.

**보급 지점 배치 방향 확정(2026-09-19 사용자 결정, D03): 주요 장거리 노선 가까이에 배치해 작은 우회로 들를 수 있게 한다.** 보급을 경유해도 여행 흐름이 이어지도록 하며, 정확한 위치·우회 거리·소요 시간은 후속 노선 설계와 플레이 실측으로 정한다. 보급을 경유하는 노선은 지점까지 도달하는 데 필요한 연료와 보급 후 다음 구간·귀환에 필요한 여유를 함께 검증한다.

**2026-09-20 프로토타입 1단계 구현**: 일관된 소비 모델을 먼저 넣었다. 순항 0.15%/초, 출력 보조 0.4%/초, 활공 0%/초, 용량 100%이며 자동 착륙·전달·이륙 구간과 지상 정지 중에는 소비하지 않는다. 오른쪽 위 게이지와 30%·15% 경고를 함께 넣었고, 고갈 시 엔진이 멈춰 활공으로 바뀐다. 모두 하루 흐름 실측에서 역산한 초기값이며 장거리 노선·보급 지점은 아직 없다. 측정값은 [측정 기록](P.프로토타입_측정기록.md)을 따른다.

연료 소비를 거리 경계에서 갑자기 켜는 대신, 일관된 소비 모델과 노선 길이·연료 여유로 차이를 만드는 안을 우선 시험한다. 가까운 배달에서 불필요하게 게이지를 감시하지 않아도 되는지 확인한다.

**고도 예금 차단(2026-09-21 사용자 결정, D03)**: 활강비가 9.7:1이라 연료 1%가 고도 15m, 곧 활공 145m 전진에 해당한다. 그래서 출발 직후 한 번 크게 올라가 두면 그 고도만으로 편도 10km를 덮을 수 있고, 실제 플레이에서도 연료는 출발 상승(-32.5%)과 복귀 상승(-20.3%) 두 번에만 쓰였다. 산맥·기류·보급 지점이 모두 판단 대상에서 빠지는 원인이므로, **고도가 높을수록 출력 보조 상승률이 떨어지게 한다.** 300m까지는 6.0m/s 그대로이고 그 위로 1000m에 걸쳐 최저 25%까지 선형으로 떨어진다(600m 4.2m/s, 900m 2.4m/s). 투하 후 200m 회복과 가까운 배달은 전 구간이 300m 아래라 확정된 근거리 소비율(하루 27.8%)에 영향이 없다. 활공이 무료라는 원칙과 확정된 소비율을 모두 보존하면서 장거리에서만 압박을 만드는 선택이며, 높은 고도는 연료 대신 상승기류로 얻도록 유도한다. 상승률이 70% 밑으로 떨어지면 안내를 한 번 표시하고, 최종 수치는 재측정으로 정한다.

이전의 만재 240초·엔진 사용률 제한·세 번째 마을 앞 연료 고갈 목표는 현행 기준에서 제외한다. 연료량과 소비율은 장거리 검증 때 새로 정하며, 첫 비행 검증에서는 연료 고갈로 진행을 막지 않는다.

**소비율 최종 확정(2026-09-24 사용자 결정, D03)**: 순항 **0.15%/초**, 출력 보조 **0.4%/초**(희박한 공기로 고도 300m 위부터 상승률 감소, 최소 25%), 활공 **0%/초**, 자동 구간(착륙 보조·전달·재이륙) 0, 용량 100%를 최종값으로 한다. 근거 실측: 가까운 배달 최근 11회 평균 **33.4%**(25.8~40.3%, 끝 연료 약 60~74%), 장거리 20km 왕복 **59.6%**(고개 바람 9.1 m/s·급유 없이 40.4% 도착), 1막 시험비행 12~14%. 연료로 긴장한 순간은 없었고 S는 판단으로 건너뛰었다. 여유는 조이지 않는다(쉬운 쪽 원칙). 장거리 효율은 소비율이 아니라 **활공 비율**이 결정한다(활공 79% → 2.09 %/km, 47% → 5.14 %/km). 기류는 선택이며 소비율 설계에 전제하지 않는다([측정 기록](P.프로토타입_측정기록.md)).

2026-09-19 사용자 결정(D04·D07): 큰 충돌·연료 고갈 복귀 직후에는 **복귀 위치에서 실제 비행 경로 거리가 가장 짧은 보급 지점**을 잠시 안내해 제공된 연료로 이동할 곳을 알려준다. 원래 목적지와의 거리보다 복귀 위치에서 보급 지점까지의 비행 가능 경로를 우선한다. 일시 안내 후 기존 목적지 안내로 돌아가며, 상세 규칙과 검증 항목은 [게임플레이](04.게임플레이.md)를 따른다.

경로 거리가 같은 보급 지점이 있으면 장애물 여유·착륙 접근 폭·지정 안전 상태가 더 나은 지점을 우선한다(2026-09-19 사용자 결정). 안전성 평가와 동률 처리 기준은 후속 노선 검증에서 구체화한다.

복귀 시 제공된 연료가 선택된 보급 지점까지 부족해도 해당 보급 지점을 안내하고 출발을 허용한다(2026-09-19 사용자 결정). “보급 지점까지 연료 부족 예상” 경고를 함께 표시하며, 출발 제한이나 자동 지점 변경은 하지 않는다. 플레이어가 다른 경로·착륙 지점을 판단한다. 복귀 직후 보급 지점 안내는 5초 동안 표시하며, 이 시간에는 방향을 바꿔도 처음 선택한 지점을 유지한 뒤 기존 목적지 안내로 돌아간다(2026-09-19 사용자 결정).

연료 고갈 후에는 D04의 확정 원칙에 따라 큰 충돌과 동일한 짧은 암전을 거쳐 우체국·지정 착륙 지점을 활용한 가까운 안전 지점 근처 공중으로 복귀한다(2026-09-19 사용자 결정). 화면이 돌아오면 비행 중인 상태에서 즉시 일반 비행 조작을 재개할 수 있게 한다. 복귀 시 가까운 보급 지점까지 비행할 수 있는 연료를 제공한다(2026-09-18 사용자 결정). 구체적인 양은 복귀 위치에서 보급 지점까지의 이동·접근·착륙 조건을 포함해 실측으로 정한다. 진행 보존과 복귀 규칙은 [게임플레이](04.게임플레이.md)에서 관리한다. 첫 비행 검증에서는 연료 고갈을 비활성화하고, 장거리 후속 검증에서 복귀 후 보급 지점까지 도달해 재도전을 이어갈 수 있는지 확인한다.

## 4. 바람과 날씨

### 바람의 역할

바람은 환경 효과가 아니라 **핵심 게임플레이 시스템**이다.

바람은 다음 요소에 영향을 준다.

- 비행 속도
- 이동 방향
- 활공 효율
- 상승기류
- 연료 효율
- 비행 난이도
- 경로 선택

---

### 바람의 기본 상태

### 무풍

- 엔진 의존도가 높다.
- 활공 효과가 낮다.
- 비교적 안전하다.
- 장거리 이동에는 비효율적이다.

### 순풍

- 이동 속도가 증가한다.
- 장거리 이동에 유리하다.
- 연료 효율이 좋아질 수 있다.

### 역풍

- 이동 속도가 감소한다.
- 엔진 출력이 증가할 수 있다.
- 연료 소비가 증가할 수 있다.

### 측풍

- 진행 방향에서 기체가 밀려난다.
- 플레이어의 조종 판단이 필요하다.

### 상승기류

- 고도를 확보할 수 있다.
- 활공으로 연결할 수 있다.
- 숙련 플레이의 핵심 요소다.

### 하강기류

- 고도를 잃는다.
- 상승기류와의 연결을 끊을 수 있다.

---

### 날씨별 플레이 경험

날씨별 플레이 경험의 설계안은 다음과 같다.

| 날씨 | 게임플레이 특성 | 주요 경험 |
|---|---|---|
| 맑은 아침 | 무풍 | 평온 |
| 맑은 오후 | 상승기류 | 자유 |
| 흐림 | 불규칙한 기류 | 집중 |
| 강풍 | 강한 순풍/역풍 | 판단 |
| 안개 | 시야 제한 | 정적 |
| 폭풍 | 비행 불가 | 휴식 |

### 날씨 진행 방식 — 고정 장면과 제한적 변화

2026-09-18 사용자 결정(D08): 중요한 장면은 정해진 날씨로 연출하고, 일반 배달에서는 비행 가능한 범위 안에서 풍향·세기에 작은 변화를 준다.

- 1막의 첫 비행·벨로아 주변은 맑은 오후, 2막의 아르덴느 진입·산악 노선은 흐림과 강풍, 3막의 마지막 노르드발 노선은 안개로 고정한다. 2막 전환 직후에는 한 번의 폭풍 휴식 장면을 배치한다. 이 장면들은 학습·전환·엔딩의 감정을 고정하며, 일반 배달의 제한적 변화와 구분한다.
- 일반 배달의 변화는 기체·노선의 비행 및 당일 귀환 가능 범위로 제한한다. 2026-09-18 사용자 결정(D08): 첫 테스트의 일반 배달은 배달당 한 번 이하, 풍향·세기 최대 ±10% 변화로 시작한다. 변화 20초 전부터 구름의 움직임·바람 소리·스카프 흔들림으로 예고하고 10초에 걸쳐 서서히 전환한다. **바람 변화 자체는 별도 HUD 문구를 띄우지 않고 월드 단서만 사용한다(2026-09-19 사용자 결정). 전환이 끝난 뒤의 바람은 해당 배달이 끝날 때까지 유지하고, 다음 배달은 기본 바람 조건에서 시작한다(2026-09-19 사용자 결정).** 변화 폭·빈도·예고 시간·전환 속도는 실측으로 조정한다.
- 폭풍은 이야기에서 정한 휴식 장면으로만 사용한다. 무작위·연속 폭풍으로 배달이나 이야기 진행을 막지 않는다. 정해진 편지 읽기·대화를 마친 뒤 플레이어가 휴식을 선택하면 실제 시간 대기 없이 다음 날로 넘어간다. 추가 대화·정비는 선택 사항이다(2026-09-18 사용자 결정, D08). 이전의 연속 폭풍 최대 2일 가설은 현행 기준에서 제외한다.
- 기본은 당일 귀환이며, 강풍으로 다음 날 귀환을 강제하는 안은 제외한다. 하루 종료와 폭풍 장면의 행동은 [게임플레이](04.게임플레이.md)에서 관리한다.

1막 종료의 산맥 입구에는 강한 맞바람을 경험하고 귀환하는 고정 서사 장면을 둔다(2026-09-18 사용자 결정). 돌아올 수 있는 비행·연료 여유를 유지하고, 추락이나 연료 고갈을 막 전환 조건으로 삼지 않는다. 실제 바람 세기와 접근·귀환 경로는 후속 노선 검증에서 정한다.

2026-09-18 사용자 결정(D08): 기본 시간대는 업무 흐름에 맞춰 준비는 아침, 배달은 낮, 귀환·정산은 저녁으로 연출한다. 주요 서사 장면에는 지정된 시간대를 적용한다. 비행 중 시간제한으로 귀환을 재촉하지 않으며, 시간대 전환 시점·연출 길이는 후속 검증에서 정한다. 시간대 연출과 일반 배달 중 바람의 제한적 변화는 구분한다. 지역별 시간대 프리셋은 이전 참고안으로 두고 현행 업무 흐름과 서사 장면의 지정 시간대를 우선한다.

시간대 전환은 실시간 누적 시간이 아니라 상태 전환으로 처리한다. 우체국 하루 시작은 아침, 첫 이륙 뒤 배달·탐색은 낮, 마지막 귀환 후 정산은 저녁이다. 낮 비행을 오래 해도 자동 실패·강제 귀환은 없고, 폭풍 휴식에서 다음 날을 선택하면 아침 상태로 초기화한다.

## 5. 스카프 피드백

스카프는 단순한 장식이 아니다.

플레이어가 바람의 상태를 직관적으로 인식할 수 있도록 하는 **월드 기반 피드백 장치**다.

```text
바람 약함
→ 스카프의 움직임 작음

바람 강함
→ 스카프 크게 흔들림

방향 변화
→ 스카프 방향 변화
```

UI에서 숫자를 확인하지 않아도 플레이어가 하늘의 상태를 느낄 수 있어야 한다.

스카프는 동시에 아버지의 유품이라는 서사적 의미를 가진다.

## 6. 조정 가능한 변수

초기에는 다음 값을 고정하지 않고 조정 가능한 변수로 둔다.

| 변수 | 목적 |
|---|---|
| Max Speed | 최고 속도 |
| Cruise Speed | 순항 속도 |
| Climb Rate | 상승 속도 |
| Glide Ratio | 활공 효율 |
| Fuel Capacity | 최대 연료 |
| Fuel Consumption | 연료 소비 |
| Wind Speed | 바람 세기 |
| Wind Influence | 바람이 기체에 미치는 영향 |
| Updraft Strength | 상승기류 세기 |
| Updraft Radius | 상승기류 범위 |
| Turbulence | 난기류 강도 |
| Visibility | 시야 |
| Collision Feedback | D04 확정 원칙: 가벼운 접촉은 흔들림·소리 후 비행 지속, 큰 충돌로 비행이 어려우면 짧은 암전 후 안전 지점 복귀(2026-09-19 사용자 결정). 판정 기준·연출 강도·암전 길이는 실측 조정. 첫 완성판의 누적 내구도·부품별 고장은 제외. 상세 규칙은 [게임플레이](04.게임플레이.md)를 따른다 |

이 값들은 문서상의 확정값이 아니라 **플레이 테스트를 통해 조정해야 하는 Prototype Variables**다.

> 아래는 기존 종합 기획서의 참고안이다. 현재 입력 방향은 3.3절, 실패 후 복귀와 기체 역할은 게임플레이의 확정 원칙(D04·D05)을 따른다. 아래 수치·자동 착륙·추락 제거는 일괄 채택하지 않았다. 기체별 세부 성능은 후속 검증에서 정한다.

## 7. 이전 조작·물리 후보

핵심 원칙은 **"플레이어는 자세만 만든다. 나머지는 게임이 처리한다"** 이다.

### 3.1 플레이어가 하는 것

| 입력 | 동작 |
|---|---|
| 왼쪽 스틱 위·아래 | 기수를 올리고 내린다 |
| 왼쪽 스틱 좌·우 | 기울이면 그쪽으로 선회한다 |
| 오른쪽 트리거 | 엔진 출력, 잠깐 빨라진다 |
| 왼쪽 트리거 | 엔진을 끄고 활공한다 |

### 3.2 게임이 알아서 하는 것

| 요소 | 처리 방식 |
|---|---|
| 방향타 | 선회할 때 자동으로 조율 |
| 속도 | 항상 안전 범위로 복귀 |
| 실속·추락 | 아예 존재하지 않는다 |
| 착륙 | 활주로 근처에 가면 자동 접지 |

### 3.3 스로틀이 없다

엔진은 항상 켜져 있고 일정 순항 속도를 유지한다. 트리거는 "가속" 버튼이 아니라 **"잠깐의 여유"** 를 주는 버튼이다.

---

### 이전 비행 물리안

Chaos Vehicle을 쓰지 말 것. 커스텀 Pawn과 자체 이동 로직이 훨씬 낫다. 진짜 양력 공식이 아니라 **감정 곡선**을 만드는 것이 목표다.

```
목표속도 = 순항속도 + (기수각 × 중력계수)      // 내려가면 빨라지고, 올라가면 느려진다
현재속도 = Lerp(현재속도, 목표속도, 0.8 × dt)   // 아주 느린 보간 = 묵직한 관성

최저속도 아래로는 절대 내려가지 않음            // 실속 제거
롤 입력 → 요(yaw)를 30~40% 자동 커플링          // 러더 조작 없이도 예쁜 선회
입력이 없으면 3초에 걸쳐 수평으로 복귀           // 손을 놓으면 알아서 안정
```

이 네 줄이 게임의 90%다. **다른 것을 만들기 전에 이것부터 2주간 다듬는다.** 회색 박스 지형에서 30분 날았을 때 기분이 좋지 않으면, 아무리 예쁜 배경을 깔아도 살아나지 않는다.

### 이전 고도 획득안

| 방식 | 상승률 | 의도 |
|---|---|---|
| 엔진 상승 | 초당 3~4m (답답할 정도로 느리게) | 고도를 귀한 자원으로 만든다 |
| 상승기류 | 초당 15m 이상 | "구름 위로 올라간다"를 보상으로 만든다 |

상승기류 위치는 새떼, 굴뚝 연기, 한쪽으로 기울어진 나무로 시각화한다. UI 아이콘으로 표시하지 않는다.
