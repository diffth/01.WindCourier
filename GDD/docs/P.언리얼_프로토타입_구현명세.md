# 바람 배달부 — 언리얼 최소 비행 프로토타입 구현 명세

> 상태: 최소 비행·기류·투하 C++ 구현, 자동 검증 통과 · Unreal Engine 5.8 · 플레이 실측 전

현재 구현은 `WindCourier/Source/WindCourier/Flight/`의 C++ 액터를 사용한다. 아래 `BP_` 이름은 역할을 설명하는 설계 이름이며 같은 이름의 Blueprint 에셋 생성 완료를 뜻하지 않는다. 기류 범위는 원통형 거리·높이 검사로 판정하고, 기존 `LV_FlightTest`에는 실행 시 테스트 액터를 생성한다. [실행 안내](../../WindCourier/FLIGHT_TEST.md)에 조작·배치 가설·측정 필드·현재 한계를 기록한다.

[프로토타입 검증](P.프로토타입검증.md)에서 정한 최소 범위를 실제 프로젝트에 옮기기 위한 명세다. 프로젝트 생성 후 이 순서대로 구현하고, 수치는 플레이 테스트 전까지 기본값으로만 취급한다.

## 1. 레벨 구성

`LV_FlightTest` 레벨에 다음만 배치한다.

| 요소 | 수량 | 역할 |
|---|---:|---|
| `BP_CourierJenny` | 1 | 플레이어 비행체와 카메라 |
| 출발 지점 A | 1 | 시작 위치와 초기 방향 |
| `BP_ThermalVolume` | 4~6 | 상승기류의 반경·고도·지속 시간 검증 |
| 평야·계곡·능선 회색 박스 | 각 1 | 기류를 관찰하고 경로를 고르는 지형 |
| `BP_DropZone` | 1 | 넓은 저공 투하 구역 B |
| `BP_TestHUD` | 1 | 목적지 방향, 엔진 상태, 투하 가능 표시 |

첫 레벨에는 마을 외형, NPC, 착륙 전달, 장거리 연료, 이동하는 상승기류를 넣지 않는다.

## 2. 입력과 비행 상태

Enhanced Input에 다음 액션을 만든다.

| 액션 | 게임패드 | 키보드 | 처리 |
|---|---|---|---|
| `IA_Steer` | 왼쪽 스틱 | WASD | 기체 방향·자세 조정 |
| `IA_PowerAssist` | RT 홀드 | Left Shift 홀드 | 상승·출력 보조 |
| `IA_ToggleGlide` | LT 1회 | Left Ctrl 1회 | 순항과 활공 전환 |
| `IA_DropInteract` | A 또는 지정 버튼 | E | 투하 가능할 때 배달 성공 |

`BP_CourierJenny`의 상태는 `Cruise`, `PowerAssist`, `Glide` 세 가지로 둔다. LT와 Ctrl은 누르는 동안 반복 전환하지 않는다. 활공 중 RT를 누르면 활공을 해제하고 출력 보조 상태로 전환한다. RT를 놓으면 순항으로 돌아간다.

## 3. 기류와 투하 판정

`BP_ThermalVolume`은 Box 또는 Sphere Collision을 사용한다. 인스턴스 편집 변수는 `EffectiveRadius`, `MinAltitude`, `MaxAltitude`, `LifetimeSeconds`, `LiftStrength`로 둔다. 첫 시험의 지속 시간은 맑은 날 90~180초, 흐린 날 60초다.

`BP_DropZone`은 플레이어가 중심점 반경 80m 이내, 고도 120m 이하, 상승 중이 아닐 때(수직 속도 +0.5 m/s 미만, 2026-09-19 변경) `CanDrop`을 켠다. `IA_DropInteract`가 조건 안에서만 우편을 완료하고, 조건 밖 입력은 우편을 소모하지 않는다. 통과 후에는 목적지에 다시 접근할 수 있어야 한다.

## 4. 측정 로그

`BP_FlightTelemetry`를 비행체에 붙이고 다음 이벤트를 기록한다.

- 상태 전환 시각과 상태별 누적 시간
- 기류 생성·진입·이탈·소멸 시각
- 최고·최저 고도
- 투하 가능 진입, 투하 시도, 재접근 횟수
- 투하 후 기류 유효 고도까지 회복하는 시간
- 전체 비행 시간과 탐색·상승·활공 구간 시간

테스트 중에는 화면 로그를 사용하고, 반복 측정 단계에서는 한 회 비행을 CSV로 저장한다. 기록 필드는 [프로토타입 검증](P.프로토타입검증.md) 1.4절의 측정 항목과 같은 이름을 사용한다.

## 5. 구현 순서와 통과 조건

1. 빈 레벨에 Jenny Pawn, 카메라, Enhanced Input을 연결한다.
2. 순항·출력 보조·활공 상태 전환을 구현하고 HUD로 상태를 표시한다.
3. 기류 하나에서 상승력을 확인한 뒤 4~6개로 늘린다.
4. 목적지 방향과 투하 가능 표시를 추가한다.
5. 투하 후 출력 보조만으로 기류 유효 고도에 복귀할 수 있게 조정한다.
6. 텔레메트리 로그를 켜고 140초 마이크로 루프를 3회 측정한다.

최소 통과 조건은 기류를 직접 찾고, 투하 구역을 지나쳐도 우편을 잃지 않으며, 출력 보조만으로 고도를 회복해 비행을 이어가는 것이다. 이 조건을 통과하기 전에는 수채화 머티리얼·마을·서사 시스템을 확장하지 않는다.

## 6. 다음 미결사항 — 키보드 사용성 검증

첫 실행에서는 게임패드와 키보드를 같은 비행 구간에서 번갈아 사용한다. 키 배치는 WASD, Left Shift, Left Ctrl, E로 고정해 비교하고, **동일 구간을 추가 플레이 3회** 반복한다. 재배치 기능은 입력 피로가 확인된 뒤 추가한다.

| 확인 항목 | 테스트 방법 | 기록할 문제 |
|---|---|---|
| 방향 조작 | 30초 동안 직선·완만한 선회·급선회를 각각 수행 | 손가락 이동, 과도한 입력, 방향 반전 실수 |
| 출력 보조 | Shift를 1초·3초·10초씩 홀드 | 홀드 시간 혼동, 상승 시작 지연, 해제 후 상태 오류 |
| 순항·활공 전환 | Ctrl을 짧게 5회 누르고 활공 중 다시 전환 | 반복 전환, 상태 표시 불일치, 실수 입력 |
| 동시 입력 | Shift 홀드 중 Ctrl 입력, 해제 직후 Ctrl 입력 | 상태가 튀는지, 입력이 유실되는지 |
| 투하 상호작용 | E를 조건 안·조건 밖에서 각각 3회 입력 | 우편 소실, 표시와 판정 불일치, 손가락 이동 부담 |

각 테스트 뒤 플레이어가 `손이 편한가`, `현재 비행 상태를 바로 알 수 있는가`, `입력을 다시 배우지 않고 이어갈 수 있는가`를 1~5점으로 답한다. **추가 플레이 3회**를 각각 독립 기록으로 남긴다. 평균 3점 미만이거나 같은 실수가 두 번 반복되면 키 배치·상태 피드백을 조정하고 동일 구간을 다시 측정한다. 3회 기록과 조정 결과 확인이 끝날 때까지 미결사항의 키보드 사용성 검증은 완료로 표시하지 않는다.

## 7. 다음 미결사항 — 투하 구현 세부 검증

투하 판정은 한 번에 한 변수만 바꾸며 비교한다. 첫 실행값은 현재 가설인 중심점 반경 80m, 고도 120m 이하, 상승 중이 아님(수평 포함)이다. 각 조건에서 접근 방향을 정면·측면·비스듬한 방향으로 나누고, 구역을 지나친 뒤 재접근하는 경우도 포함한다.

| 실험 | 비교값 | 통과 기준 |
|---|---|---|
| 구역 반경 | 60m / 80m / 100m | 표시가 켜진 뒤 한 번의 자연스러운 입력으로 성공하는가 |
| 허용 고도 | 100m / 120m / 150m | 저공 접근 표시와 실제 투하 판정이 일치하는가 |
| 하강 판정 | 하강 중만 / 하강·수평 / 속도 여유 추가 | 지나가는 순간의 억지 조작 없이 성공하는가 |
| 접근 방향 | 정면 / 측면 / 비스듬함 | 방향에 따라 표시가 늦거나 판정이 흔들리지 않는가 |
| 재접근 | 구역 통과 후 선회해 재진입 | 실패 입력이나 통과만으로 우편이 소모되지 않는가 |

각 조합을 3회씩 실행하고 `표시가 켜진 시점`, `입력부터 성공까지의 시간`, `재접근 횟수`, `우편 소실 여부`, `판정이 늦었다고 느낀 횟수`를 기록한다. 표시가 켜졌는데 3회 중 한 번이라도 조건 밖에서 성공하거나, 조건 안인데 두 번 이상 성공하지 않으면 판정과 표시를 함께 조정한다. 목표는 정밀 조준이 아니라 넓은 구역에 진입했다는 판단만으로 한 번에 배달하는 것이다.

이 검증이 끝날 때까지 반경·허용 고도·하강 판정의 최종값은 확정하지 않는다. 결과는 [프로토타입 검증](P.프로토타입검증.md)의 투하 판정·재접근 측정 항목과 함께 기록한다.

## 8. 다음 미결사항 — 투하 후 고도 회복 검증

투하 직후에는 같은 출발 조건에서 두 경로를 비교한다. 첫 번째는 상승기류에 들어가지 않고 `PowerAssist`만 사용하는 경로이고, 두 번째는 주변 상승기류를 찾아 진입하는 경로다. 월드의 바람·상승기류는 두 실험에서 동일하게 유지한다.

| 측정값 | 기록 방법 | 판단 기준 |
|---|---|---|
| 회복 시간 | 투하 성공부터 기류 유효 고도 하한 도달까지 | 출력 보조만으로 회복 가능한가 |
| 회복 거리 | 투하 지점에서 유효 고도 도달 위치까지 | 재접근에 과도한 선회가 필요한가 |
| 엔진 사용 시간 | `PowerAssist` 누적 시간 | 가까운 배달에서 연료 부담이 과하지 않은가 |
| 기류 경로 이점 | 기류 사용 여부별 회복 시간·고도 비교 | 기류를 찾을 이유가 체감되는가 |
| 비행 재개 체감 | 회복 직후 30초 활공 | 다시 날고 싶다는 흐름이 유지되는가 |

각 경로를 3회씩 실행하고, 출력 보조만으로 3회 모두 유효 고도에 도달하지 못하면 상승력·투하 고도·기류 유효 고도 중 하나만 조정해 재시험한다. 출력 보조 경로가 회복 가능해야 하며, 기류 경로는 더 짧거나 안정적인 회복을 제공해야 한다. 기류를 사용하지 않으면 회복할 수 없도록 수치를 맞추지 않는다.

회복 중 지형 충돌이나 기류 소멸이 발생하면 실패 원인을 `조작`, `지형 배치`, `기류 수명`, `상승력`으로 분리해 기록한다. 이 결과가 쌓이기 전에는 능선 바람을 추가하지 않는다.

## 9. 다음 미결사항 — 기류 지속 시간 검증

기류는 같은 위치와 같은 강도로 배치하고 지속 시간만 바꿔 비교한다. 맑은 날은 90초·135초·180초, 흐린 날은 60초를 첫 시험값으로 사용한다. 기류가 생성될 때와 사라지기 20초 전에는 새떼·구름·바람 소리 같은 월드 단서를 함께 표시한다.

| 측정값 | 기록 방법 | 실패 신호 |
|---|---|---|
| 탐색 성공률 | 기류가 생성된 뒤 제한 시간 안에 발견·진입한 횟수 | 단서를 봐도 위치를 추측하기 어려움 |
| 진입 후 상승 완료율 | 진입 후 유효 고도까지 도달한 횟수 | 상승 중 소멸로 반복 실패 |
| 남은 시간 인지 | 소멸 예고 후 경로를 바꾼 횟수 | 예고가 늦거나 알아차리지 못함 |
| 지속 시간 체감 | 각 비행 뒤 1~5점 평가 | 1점은 운에 의존한다고 느낌 |

각 지속 시간 조건에서 최소 3회 비행한다. 도착 전에 소멸하거나 상승 중 자주 사라져 성공이 운에 좌우되면 지속 시간을 늘리기보다 먼저 단서 거리·예고 시점·기류 배치를 조정한다. 탐색이 지나치게 쉽고 경로 선택이 사라지면 단서 강도나 기류 간격을 낮춘다.

최종값은 마이크로 루프 140초와 함께 판단한다. 기류가 한 번의 루프 안에서 최소 한 번은 찾아 쓸 수 있어야 하지만, 모든 기류가 항상 남아 있어야 하는 것은 아니다. 흐린 날 60초는 변덕을 느끼게 하는 예외값으로 유지하되, 투하 후 고도 회복을 막는 수준이면 후속 연료·기체 실험 전에 다시 조정한다.

## 10. 다음 미결사항 — 능선 바람 비교 실험

능선 바람은 최소 비행 검증을 통과한 뒤 같은 회색 박스 지형에 선택적으로 추가한다. 능선 바람이 있는 빌드와 없는 빌드에서 출발점 A, 투하 구역 B, 일반 상승기류의 위치·강도·지속 시간을 동일하게 유지한다.

| 비교 항목 | 기록 방법 | 채택 신호 |
|---|---|---|
| 경로 선택 | 능선 접근·우회·직선 경로 선택 횟수 | 능선이 실제 선택지로 작동함 |
| 고도 회복 | 투하 후 유효 고도까지 시간·거리 | 엔진만 쓰는 것보다 명확히 쉬움 |
| 관찰 필요성 | 능선의 바람 단서를 확인한 횟수 | 지형을 외우지 않고 관찰함 |
| 반복성 | 같은 노선을 3회 반복한 경로 변화 | 한 번 외우면 판단이 사라지지 않음 |
| 체감 | `경로를 고르는 재미가 있었는가` 1~5점 | 평균 3점 이상 |

능선 바람이 단순한 지름길로만 작동하거나, 위치를 외우는 것만으로 판단이 끝나거나, 엔진 출력 회복보다 필요성이 낮으면 첫 완성판에서는 보류한다. 반대로 주변 단서로 발견할 수 있고 경로 선택과 고도 회복을 함께 개선하면 제한된 산악 노선에만 적용한다. 이 실험 전에는 능선 바람을 기본 레벨에 포함하지 않는다.

## 11. 다음 미결사항 — 착륙 전달 후 재이륙 검증

착륙 보조는 플레이어가 직접 접근하되 속도·고도·방향의 넓은 허용 범위에서 마지막 접지와 정지를 보조한다. 약간의 오차는 흡수하고 범위를 벗어나면 재접근한다. 정확한 임계값은 재이륙과 함께 검증한다.

재이륙은 착륙 전달 프로토타입에서 검증한다. 착륙 지점과 이륙 지점을 분리하고, 전달·대화가 끝난 뒤 카메라를 1.5초 전환한다. 이후 짧은 활주와 지면 이탈은 자동으로 진행하고, 이륙 직후 일반 비행 조작으로 복귀한다.

| 확인 항목 | 비교값 | 기록할 문제 |
|---|---|---|
| 이륙 지점 | 착륙 지점 바로 옆 / 20~40m 전방 | 자동 활주 경로가 막히거나 이륙 후 방향을 읽기 어려운지 |
| 카메라 전환 | **1.5초 전환 + 기체 뒤쪽 1초 표시(확정)** | 전환 중 조작 상실, 후방 구도 어색함, 전달 장면의 여운 부족 또는 과도한 지연 |
| 활주 보조 | **강한 자동 활주·이륙(확정)** | 자동 연출처럼 느껴지는 정도, 지면 이탈 실패, 이륙 직후 조작 복귀 |
| 재이륙 시간 | 전달 완료부터 자동 지면 이탈까지 | 대화 흐름이 끊길 만큼 길거나 조작 복귀가 늦는지 |
| 재이륙 연료 | **가까운 배달 기본량(확정)** | 착륙 전달·재이륙 후 다음 기류·목적지까지 부담이 생기는지 |

각 조합을 3회씩 실행한다. 전달 완료 뒤 자동 활주·이륙이 짧게 진행되고, 지면에 걸리거나 긴 수동 활주를 반복하지 않아야 한다. 지면을 벗어난 뒤 기체 뒤쪽을 1초 보여주고 기존 비행 카메라로 자연스럽게 복귀해야 한다. 후방 구간이 끝나기 전 입력은 무시하고 이후 일반 비행 조작을 활성화한다. 가까운 배달에서는 재이륙 자체가 실패 원인이 되지 않아야 하며, 연료 여유는 장거리 규칙과 섞지 않고 별도로 기록한다. 카메라 전환과 자동 이륙 중 새 입력이 상태를 망가뜨리지 않는지 함께 확인한다.

2026-09-19 구현: `AFlightLandingSite`(C)가 접근 허용 범위 판정, E로 시작하는 착륙 보조(곡선 하강·40m 감속 활주), E 1회 전달 장면, 1.5초 전환·2초 활주·1초 후방 카메라의 자동 재이륙, 활주 경로 막힘 시 무기한 대기를 담당한다. 초기값과 자동 검사 결과는 [측정 기록](P.프로토타입_측정기록.md)에 있다. 이륙 지점 비교는 `TakeoffOffset`으로 바꿔 3회씩 실행한다.

## 14. 다음 미결사항 — 엔딩 후 구현 검증

엔딩 후에는 우체국에서 자유 비행을 재개하고, 하루를 마치면 다음 게임 내 날에 기존 노선의 정규 우편을 갱신한다. 엔딩과 완료한 서사 편지는 다시 재생하지 않으며, 미완료 선택 편지는 별도 상태로 계속 보유한다.

| 확인 항목 | 테스트 방법 | 통과 기준 |
|---|---|---|
| 재개 위치 | 엔딩 직후와 게임 재실행 후 확인 | 우체국에서 자유 비행을 시작함 |
| 정규 우편 갱신 | 우편 선택·건너뛰기·자유 비행 후 하루 종료 | 다음 날 최대 3장의 기존 노선 카드가 생성됨 |
| 카드 정렬 | 가까운·중거리·장거리 노선을 모두 해금한 상태로 확인 | 거리 우선, 같은 거리에서는 적재 부담 우선 |
| 빈 목록 | 이용 가능한 노선이 0~2개인 상태로 확인 | 빈 슬롯을 만들지 않음 |
| 선택 편지 유지 | 1~5번 중 일부를 미완료로 남기고 엔딩 진행 | 다음 날·엔딩 후에도 상태와 조건이 유지됨 |
| 완료 기록 | 완료한 편지와 엔딩을 다시 선택 | 본문 기록만 열리고 배달 장면·대화는 재생되지 않음 |

정규 우편 카드는 목적지·거리·적재량·장거리 표시·예상 왕복 연료를 포함해야 한다. 카드 문구와 정렬 예외는 실제 목록이 1개·2개·3개일 때 각각 3회 확인하고, 엔딩 직후·재실행·하루 종료 후에도 완료 편지·엔딩이 반복되지 않는지 확인한다. 이 테스트가 끝날 때까지 최종 문구와 예외 순서는 확정하지 않는다.

## 15. 다음 미결사항 — 기체별 최종 수치 검증

기체 비교는 같은 노선·같은 날씨·같은 기류 배치에서 수행한다. 월드의 바람과 상승기류를 기체별로 바꾸지 않고, 기체의 반응 차이만 측정한다. 첫 테스트는 현재 비행·코어 루프 문서의 표를 그대로 사용한다.

**2026-09-24 개정**: 기류가 선택이 되고 적재 규칙을 넣지 않기로 하면서 아래 표의 "상승·선회(같은 기류 진입)"와 "적재" 행은 더 이상 쓰지 않는다. 현재 절차는 [프로토타입 검증](P.프로토타입검증.md)의 "후속 기체 비교 측정" 개정안 — 수치는 자동 테스트로 확인하고, 사람 플레이는 가까운 배달·장거리에서 기체만 바꿔 하루 시간·소비·접촉·활공 비율을 비교한다. 아래 표는 기록용으로 남긴다.

| 측정 항목 | 방법 | 역할 확인 기준 |
|---|---|---|
| 상승·선회 | 같은 기류에 진입해 유효 고도까지 걸린 시간과 선회 입력 횟수 측정 | Jenny가 가장 쉽게 진입·선회함 |
| 활공 | 같은 고도에서 엔진을 끄고 90초 비행 | Mailwing의 활공 거리·고도 유지가 가장 큼 |
| 적재 | 같은 노선에서 적재량을 바꿔 상승·선회 변화를 기록 | DH-4가 적재 부담에 가장 안정적임 |
| 장거리 | 같은 왕복 노선에서 엔진 사용 시간·잔여 연료 기록 | DH-4가 장거리 판단에 가장 유리함 |

각 기체를 최소 3회씩 측정하고 평균과 편차를 함께 기록한다. 성능 차이가 역할을 이해할 수 없을 만큼 크거나 세 기체의 체감이 겹치면 속도·조종성·적재·항속·활공 수치를 한 번에 여러 개 바꾸지 않고 하나씩 조정한 뒤 같은 조건으로 재측정한다. 기체 전용 의뢰나 개조 수치는 이 검증에 포함하지 않는다. 세 역할이 이해되는 결과를 얻을 때까지 D05 최종 수치 검증은 미결로 유지한다.

## 16. 다음 미결사항 — 일반 배달 날씨 변화 검증

일반 배달에서는 한 배달에 한 번 이하로 풍향·세기를 바꾼다. 첫 시험값은 최대 ±10%, 변화 예고 20초, 10초 동안의 점진 전환이다. 주요 서사 장면의 고정 날씨와 폭풍 휴식 장면에는 이 시스템을 적용하지 않는다.

| 확인 항목 | 비교값 | 통과 기준 |
|---|---|---|
| 변화 폭 | ±5% / ±10% / ±15% | 경로 판단은 바뀌지만 당일 귀환은 가능함 |
| 예고 시간 | 10초 / 20초 / 30초 | 단서를 보고 경로를 바꿀 여유가 있음 |
| 전환 속도 | 5초 / 10초 / 20초 | 갑작스러운 조작 실패가 발생하지 않음 |
| 발생 빈도 | 배달당 0회 / 1회 / 2회 | 날씨 감시가 주된 일이 되지 않음 |
| 고정 장면 격리 | 일반 배달·서사 배달·폭풍 휴식 각각 실행 | 고정 날씨가 무작위로 바뀌지 않음 |

각 조건을 3회씩 실행하고, 풍향 변화 전후의 경로 수정 횟수·귀환 시간·충돌·기류 탐색 실패를 기록한다. 변화가 있어도 비행 가능한 범위와 당일 귀환 가능성을 유지해야 하며, 변화가 눈에 띄지 않으면 폭을 키우기 전에 구름·스카프·바람 소리의 예고 전달력을 먼저 조정한다. 이 검증이 끝날 때까지 변화 폭·빈도·예고 시간의 최종값은 확정하지 않는다.

| 위험 경고 | 지형·충돌 위험을 의도적으로 가까이 통과 | 평소 화면을 가리지 않고 위험만 알림 |
| 진단 화면 끄기 | 숫자 고도·정확한 연료를 숨긴 채 비행 | 월드 단서와 간단한 표시만으로 기류·상태 파악 가능 |
| 안개 대비 | 시야를 낮춘 구간에서 동일 테스트 | 목적지·엔진 상태·상황별 알림은 유지됨 |

각 조건을 3회씩 실행하고 표시 지속 시간·놓친 알림·과도한 확인 입력 횟수를 기록한다. 알림이 없어도 안전하게 진행할 수 있어야 하며, 표시를 늘려 기류 탐색을 대신하게 만들지 않는다. 임계값과 지속 시간은 이 측정 뒤에만 조정한다.

## 18. 다음 미결사항 — 충돌·안전 지점·복귀 검증

충돌 검증은 가벼운 접촉과 비행을 계속할 수 없는 큰 충돌을 분리한다. 안전 지점은 우체국과 지정 착륙 지점 중 현재 위치에서 가장 가까우며 육안으로 식별 가능한 곳을 사용한다.

| 확인 항목 | 테스트 방법 | 통과 기준 |
|---|---|---|
| 가벼운 접촉 | 낮은 속도로 지형·표지에 접촉 | 흔들림·소리만 재생되고 비행을 계속함 |
| 큰 충돌 | 높은 속도 또는 큰 각도로 충돌 | 짧은 연출 뒤 가까운 안전 지점으로 이동함 |
| 안전 지점 선택 | 우체국·착륙 지점을 여러 거리로 배치 | 가장 가까운 식별 가능한 지점을 선택함 |
| 복귀 상태 | 충돌 후 기체·조작·카메라 확인 | 즉시 조종 가능하고 진행 기록이 유지됨 |
| 복귀 연료 | 가장 가까운 보급 지점까지의 예상량에 20%를 더함 | 보급 전까지 다시 이동할 수 있음 |
| 재도전 | 복귀 후 같은 배달을 다시 선택 | 완료 배달·단서는 유지되고 미배달 편지만 재시도함 |

각 충돌 유형과 안전 지점 조합을 3회씩 실행한다. 수리비·누적 내구도·하루 전체 재시작은 테스트에 넣지 않는다. 큰 충돌 판정이 너무 쉽게 발생하면 속도·각도·충돌 부위를 하나씩 조정하고, 가벼운 접촉이 복귀로 처리되면 임계값을 낮춘다.

## 19. 다음 미결사항 — 장거리 연료 검증

장거리 검증은 가까운 배달과 분리해 진행한다. 출발 전에 목적지·예상 왕복 연료·중간 보급 가능 여부를 표시하고, 실제 소비는 순항·출력 보조·재접근·재이륙으로 나눠 기록한다.

| 확인 항목 | 테스트 방법 | 통과 기준 |
|---|---|---|
| 거리 기준 | 가까운·중거리·장거리 노선을 같은 기체로 비교 | 장거리만 연료 판단이 필요함 |
| 소비량 | 상태별 연료 소비를 각각 기록 | 예상 왕복량과 실제값의 차이를 확인함 |
| 왕복 여유 | 출발량 100%·120% 조건 비교 | 귀환 판단이 가능하고 불필요한 고갈이 없음 |
| 중간 보급 | 표시된 지정 착륙 지점에서 E 입력 | 짧은 상호작용으로 보급되고 경로가 이어짐 |
| 출발 안내 | 카드와 지도 정보를 확인한 뒤 출발 | 거리·적재·연료·보급 가능 여부를 이해함 |
| 고갈 복귀 | 연료를 의도적으로 부족하게 설정 | 가까운 안전 지점으로 복귀하고 재도전 가능함 |

가까운·중거리·장거리 노선을 각각 3회씩 측정하고 소비량은 기체별로 분리 기록한다. 첫 장거리 테스트에서는 연료 고갈을 실패 페널티로 사용하지 않으며, 보급량·비용·정확한 장거리 기준은 왕복 시간과 함께 조정한다. 예상량과 실제 소비의 차이가 크면 카드 표시와 소비 모델을 함께 검토한다. 이 측정이 끝날 때까지 장거리 구현 세부는 미결로 유지한다.

## 20. 다음 미결사항 — 재방문 마을 세부 검증

마을은 막별 상태 3개만 사용한다. 상태가 바뀔 때 배경 소품 1~2개와 NPC 대사 묶음을 갱신하고, 편지 전달 직후에는 수취인의 짧은 텍스트·표정·동작을 한 번 재생한다. 일수마다 새 변화를 만들지 않는다.

| 확인 항목 | 테스트 방법 | 통과 기준 |
|---|---|---|
| 막 상태 갱신 | 1막 이전·2막 진입·3막 진입 후 각각 방문 | 상태마다 차이가 보이고 이전 상태로 되돌아가지 않음 |
| 편지 반응 | 전달 직후 이탈 후 재방문 | 반응은 한 번 재생되고 완료 기록이 남음 |
| 정규 우편 흐름 | 일반 투하 후 마을을 재방문 | 서사 반응이 일반 배달 흐름을 막지 않음 |
| 소품 가독성 | 비행·착륙 카메라에서 새 소품 확인 | 1~2개 변화가 눈에 띄되 목적지를 가리지 않음 |
| 늦은 전달 | 이전 막의 편지를 이후 막에 전달 | 벌점 없이 현재 상태에 맞는 짧은 반응을 보임 |
| 반복 방문 | 같은 날·다음 날·엔딩 후 방문 | 중복 대사·반복 연출이 발생하지 않음 |

각 마을의 1막 이전·2막 진입·3막 진입 후 상태와 편지 조합을 각각 3회 확인한다. 같은 날·다음 날·엔딩 후 방문에서도 완료 기록을 유지하는지 기록한다. 새 지형 에셋과 일수별 변화는 추가하지 않으며, 반응 연출이 길어 배달 흐름을 끊으면 텍스트·동작·카메라 시간을 먼저 줄인다. 최종 소품과 대사는 이 결과를 반영해 다듬는다.

## 21. 다음 미결사항 — 하루 길이와 배달 횟수 측정

하루 흐름은 정규 배달 2~3회를 기준으로 측정한다. 준비·최초 이륙·마지막 귀환·정산은 하루 공통으로 한 번만 기록하고, 이동·접근·투하·고도 회복은 배달마다 기록한다. 서사 배달은 착륙·대화·재이륙을 별도 구간으로 추가한다.

| 기록 구간 | 측정 내용 | 중복 방지 |
|---|---|---|
| 준비 | 우편 선택·기체 확인·출발까지 | 하루에 한 번 |
| 배달별 비행 | 이동·접근·투하·고도 회복 | 배달마다 분리 |
| 서사 전달 | 착륙·대화·재이륙 | 해당 배달에만 추가 |
| 탐색·정비·편지 읽기 | 실제로 소비한 시간 | 비행 시간과 별도 |
| 귀환·정산 | 마지막 배달 후 우체국 도착·정산 | 하루에 한 번 |

가까운 일반 배달 1~2회와 서사 착륙 배달 1회를 섞어 최소 3일을 측정한다. 하루 총 시간이 15분을 넘는지 자체를 실패로 보지 않고, 반복되는 대기·재접근·대화가 지루함을 만드는지 함께 기록한다. 목표 2~3시간의 메인 이야기는 하루 평균과 막별 배달 수를 곱해 추정하되, 엔딩 후 자유 비행은 계산에서 제외한다. 3일 기록이 끝날 때까지 배달 횟수와 하루 길이를 최종값으로 확정하지 않는다.

측정 후 배달 횟수·하루 길이·막별 배달 수를 함께 결정한다. 3일 평균과 막별 서사 시간을 메인 2~3시간 목표와 비교하며, 반복 피로가 크면 배달 수를 줄이고 장면 배치를 조정한다. 비행 구간만으로 분량을 산정하지 않으며, 공통 활동을 배달마다 중복 계산하지 않는다. 엔딩 후 자유 비행은 산정에서 제외한다.

## 22. 지역 확장 계획 — 아르덴느·호수 지대·노르드발 (2026-09-24 사용자 결정)

2막 편지(니코·마르타·루카스)와 3막 노선(노르바 등대)은 모두 지금 맵에 없는 지역이 필요하다. 지역을 만드는 방식과 배치를 먼저 정한다.

### 22.1 방식 — 같은 맵을 넓힌다

**새 맵을 만들지 않고 `LV_FlightTest` 한 레벨 안에 지역을 더한다.** 근거:

- GDD는 세 지역을 **하나의 생활권**으로 잇고 벨로아를 중심으로 재방문한다([게임플레이](04.게임플레이.md) 지역 배치). 핵심은 지역 사이를 날아서 오가는 것이며, 맵을 나누면 비행 중 레벨 로딩이 필요해진다.
- 다음 날·저장·`F5`가 모두 "같은 맵을 다시 연다"(`OpenLevel`)는 전제로 구현되어 있다.
- 바닥은 이미 32 km 정사각형(A 기준 ±16 km)이라 넓힐 필요가 없고, 지형은 회색 상자라 부하가 작다.
- 레벨은 지금처럼 `WindCourier/Scripts/build_flight_test_level.py`(에디터를 닫은 상태)로 만든다.

### 22.2 배치 (첫 안, 비행 실측 후 조정)

좌표는 우체국 A = (0, 0), 동쪽 +x, 북쪽 +y, 단위 km. 기존 장거리 마을 D는 이미 산맥(x = −6.5) 너머에 있으므로 **아르덴느의 정규 우편 마을로 삼는다.**

| 지역 | 장소 | 위치 | 쓰임 | 해금 (GDD) |
|---|---|---|---|---|
| 벨로아 | 우체국 A·B1·B2·C·루메 해안 | 기존 | 1막 정규 우편·에다(착륙) | — |
| 아르덴느 | D | (−10, 0) 기존 | 정규 우편(장거리) | 2막 |
| 아르덴느 | 오르델 계곡 | (−9, −4) | 니코 — 착륙 전달 | 아르덴느 진입 시 |
| 아르덴느 | 세르노 강가 | (−12, +3) | 마르타 — 착륙 전달 | 첫 산악 배달 완료 뒤 |
| 아르덴느 | 브레나 학교·정비소 | (−13, −1), 고원 | 루카스(2막)·셀마(3막 재방문) — 착륙 전달. **정비소는 보급 지점을 겸한다** | 호수 노선 해금 뒤 / 노르드발 진입 전 |
| 호수 지대 | 호숫가 마을 | (−8, +7) | 정규 우편, 아르덴느 ↔ 호수 노선 | 2막 |
| 노르드발 | 안개 구역 | y > +10 | 3막 노선 | 3막 |
| 노르드발 | 노르바 등대 | (−8, +15), 맵 북쪽 끝 해안 | 마지막 편지 — 착륙 전달 | 3막 진입(구현됨) |

- **브레나 정비소 = 보급 지점**(사용자 결정): GDD는 "정비소"라고만 적었다. 우체국에서 등대까지 편도 약 17 km이므로 이야기상으로도 연료상으로도 들를 자리가 된다. 기존 보급 지점 S(−5, +0.8)는 유지한다.
- 노르바 등대를 바닥의 북쪽 끝(y = +16)에 붙여 바닥이 끝나는 곳을 바다로 읽히게 한다.
- 각 장소의 착륙 접근 방향·고도 한계는 루메 해안 때처럼 "필수가 아닌 편지가 가장 어려운 착륙이 되지 않게" 정한다(편지 구현 세부, 2026-09-23).

### 22.3 만드는 순서

1. **아르덴느 장소**: 오르델 계곡·세르노 강가·브레나(정비소 보급 포함) → 2막 편지 3통(후보 I).
2. **호수 지대**: 호숫가 마을과 아르덴느 ↔ 호수 노선 → 루카스 편지 해금 조건이 성립한다.
3. **노르드발과 노르바 등대**: 안개 구역, 등대 착륙, 마지막 편지 배달과 엔딩(후보 G2). 안개는 이 단계에서 넣는다.

**진행(2026-09-24)**: 1단계(니코·마르타), 2단계(호수 노선 `[4]`·브레나 학교와 정비소 보급·루카스·셀마), 3단계(노르바 등대·마지막 편지·엔딩·노르드발 안개·바람이 등대 쪽으로) 모두 프로토타입 구현 완료, 비행 미확인. 같은 날 지형도 레벨 스크립트에 더했다 — 세션이 만드는 활주로(루메 포함)에 C와 같은 활주로·기둥·집, 오르델 계곡 벽, 세르노 강, 브레나 학교·정비소와 서쪽 산, 호숫가 마을 투하 지점과 호수, 노르드발 바위 언덕, 노르바 등대와 북쪽 바다. 브레나는 활주로가 지면(z = 0)에 놓이므로 고원 대신 뒤편 산으로 표현했다.

각 단계는 새 규칙 없이 기존 방식(착륙 전달·투하·보급·노선 카드)만 쓴다. 단계마다 에디터를 닫고 레벨을 다시 만든 뒤 경로·착륙 기준 검사로 기존 기준선이 바뀌지 않았는지 확인한다.
